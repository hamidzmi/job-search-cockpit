# Concentric Clean Architecture with Focused Aggregates and Pure Domain Evaluators

The Go backend is structured into concentric Clean Architecture layers (`internal/domain`, `internal/usecase`, and `internal/adapter/{http,sqlite,ai,scraper,fs}`) within a single bounded context, modeling focused domain aggregates coordinated by a SQL-agnostic transaction manager and implementing cross-aggregate triage and analytics (`Flight Deck` staleness and `Funnel Analytics`) as pure in-memory domain evaluators rather than SQL-embedded business logic.

## Context & Trade-offs

A local-first SQLite application is easy to accidentally build as anemic CRUD handlers coupled directly to SQL queries, raw LLM prompt strings, and HTML scrapers. However, the Job Search Cockpit has rich domain invariants: orthogonal `Stage` and `Outcome` transitions, distinguishing meaningful pipeline progression (`LastActivityAt`) from cosmetic edits (`UpdatedAt`), non-blocking loop `Story` de-duplication across non-cancelled `Interview Rounds`, `Offer` annualized compensation math, and stage-specific `Flight Deck` staleness rules.

- **Focused Aggregates over a God `Opportunity` Object**: `Opportunity` owns its embedded `Job Posting` value object and `Stage` / `Outcome` state transitions, while `Interview Round` (with its 1:1 `Debrief`), `Fit Assessment`, `Application Artifact`, and `Offer` are separate aggregates referencing `OpportunityID`. Cross-aggregate writes (e.g., logging an `Interaction` that advances `Opportunity.LastActivityAt`, or persisting an `Opportunity` state change alongside its `Stage Transition`) execute atomically via a `TxManager` port in `internal/usecase` backed by context-propagated SQLite transactions.
- **Pure Domain Evaluators over SQL Read-Model Logic**: Because a single candidate's search spans dozens to low hundreds of `Opportunities`, evaluating `Flight Deck` staleness/triage (`EvaluateFlightDeck`) and `Funnel Analytics` (`ComputeFunnelAnalytics`) in pure Go functions inside `internal/domain` takes sub-millisecond time while keeping every business rule 100% unit-testable with zero I/O and out of complex SQL queries.
- **Semantic Outbound Ports**: Prompt construction, OpenRouter model protocols, HTML/JSON-LD parsing, and local PDF file storage live strictly inside `internal/adapter/{ai,scraper,fs}` behind semantic domain/application ports (`AssistantGateway`, `JobPageParser`, `ArtifactBlobStore`, `BackupPort`), ensuring `internal/domain` and `internal/usecase` remain free of transport and infrastructure details.
